* Understand and Setup fold with a cap, three open, newest first (#4065)

Owner ruling 2026-09-03: admission stays total for statement and setup
rows (nothing was ever dropped for these two bands — the premise audit
found everythingTail() already exhaustive), but Understand and Setup
each show at most three moment blocks open, newest first, with the
rest behind one fold per band showing the true row count ("N more").

The cap unit is the moment block, not the underlying candidate: a
family that already shares one groupKey (coaching observations, data
quality findings) reads as one entry under one header and stays that
way, so a block never splits across open and folded — splitting it
would print its own title twice, which is what #4076's "no two blocks
share a title" guard exists to forbid. The fold's count is a row
count, not a block count, so a folded family of eight says "8 more".

The new fold reuses the app's one Disclosure primitive directly,
uncontrolled and closed by default — the same mechanism #4232 made the
page's one fold, not a second one, and stateless because
lib/disclosure-memory.ts's own allowlist holds findings-class folds
out of remembered-open state on purpose.

No new decay: rows leave the tail only by resolving, exactly as
before.
